# 产品设计

> NovaMed 及页面中的全部业务内容、人物、客户和数值均为虚构。

## 1. 产品一句话

让业务人员用自然语言完成“查数—找依据—形成建议”，并让每个关键结论都能追溯到数据或文档来源。

## 2. 为什么不是普通聊天机器人

商业分析最难的不是生成一段通顺文字，而是处理口径、计算和责任边界。普通聊天机器人可能直接给出一个听起来合理的答案；本产品要求 Agent 在回答前选择受控工具、读取实际演示数据，并把引用和执行轨迹随答案返回。

核心价值可以概括为三个词：

- **快**：减少在多个报表和制度文档之间来回查找。
- **准**：指标由代码计算，回答受数据和知识库约束。
- **可追溯**：用户可展开来源与 trace，自主判断结论是否可信。

## 3. 目标用户与高频任务

| 用户 | 典型任务 | 当前痛点 | Copilot 价值 |
|---|---|---|---|
| 销售运营 | 周报、区域/产品拆解 | 手工筛表、复制粘贴 | 一句话生成指标摘要与异常点 |
| 区域负责人 | 找下降原因、排行动优先级 | 数据与政策信息割裂 | 合并量化事实和制度依据 |
| 管理层 | 快速了解经营风险 | 报表多、追问链长 | 先给结论，再展开证据 |
| 新员工 | 查询指标口径和业务规则 | 文档分散、术语多 | 通过检索返回原始出处 |

## 4. 核心使用场景

### 场景 A：经营概览

用户问：“本周全国 NovaScan 销量怎么样？”

Agent 应识别时间、地域和产品，调用销售汇总工具，返回总量、变化、主要贡献区域、异常以及使用的数据来源。若“本周”在数据集中没有完整周期，应提示数据覆盖范围。

### 场景 B：异常诊断

用户追问：“哪个区域下降最多？为什么？”

Agent 应沿用会话上下文，先用结构化工具确定降幅，再检索活动、库存或政策知识。因果证据不足时，只能说“可能相关”或“需要进一步验证”，不能把相关性写成确定因果。

### 场景 C：规则查询

用户问：“新品进入机构渠道需要满足什么条件？”

Agent 应优先检索知识库，按条目总结规则，同时显示文档名、章节或片段。若多份文档口径冲突，应并列呈现。

### 场景 D：行动建议

用户问：“下周资源应该投到哪里？”

Agent 应把建议拆成优先级、依据、预期影响和风险。建议必须指向已计算指标或已检索规则，并明确它是决策辅助而非自动决策。

## 5. 交互设计

### 信息层级

1. **模式标识**：顶部明确显示 Local、OpenAI 或 Hybrid，避免用户误解能力来源。
2. **答案先行**：对话区先展示结论，再展示补充指标。
3. **证据后置但可见**：来源与 trace 默认折叠，标题显示数量，降低信息负担。
4. **演示边界常驻**：侧栏和页脚持续提示数据全部虚构。

### 为什么提供示例问题

示例不是装饰，而是 onboarding 和能力边界说明。四类示例覆盖概览、风险、比较和建议，让第一次使用的人在 10 秒内理解系统能做什么。

### 为什么不展示“思维链”

界面展示的是工具调用、检索和状态等可审计事件，不展示或声称展示模型的私有推理。业务用户需要的是“用了什么数据、做了什么操作、结果是否成功”，而不是冗长的内在推演文本。

## 6. 输出设计原则

一条高质量答案应尽量包含：

1. **直接结论**：先回答用户问了什么。
2. **关键数字**：说明时间、区域、产品和单位。
3. **证据**：给出数据文件或知识片段引用。
4. **判断边界**：区分事实、推断和建议。
5. **下一步**：给出能执行或能验证的动作。

不应该出现：无法验证的精确数字、真实客户或个人信息、未经证据支持的因果结论、把“模型自信”当成事实正确。

## 7. 成功指标

产品指标与模型指标分开管理：

| 维度 | 指标 | 解释 |
|---|---|---|
| 任务完成 | Task success rate | 用户是否得到可执行答案 |
| 事实质量 | 数值准确率、引用正确率 | 核心结论能否被原始数据复算 |
| 可追溯 | 来源覆盖率、trace 完整率 | 关键结论是否带证据，工具是否可审计 |
| 效率 | 端到端延迟、工具调用次数 | 是否在合理时间与成本内完成 |
| 体验 | 澄清率、重问率、用户评分 | 用户是否理解并信任输出 |
| 安全 | 敏感信息泄露率、越权调用率 | 是否守住数据和工具边界 |

具体目标值应由真实使用基线决定；演示项目通过固定黄金集展示测量方法，不虚构业务收益。

## 8. MVP 边界

MVP 包含：对话、会话上下文、销售/库存等白名单工具、轻量知识检索、来源、置信度、trace、本地模式、可选模型模式、API、自动化测试和离线评测。

MVP 不包含：真实企业数据接入、自动写回 CRM/ERP、细粒度组织权限、审批流、实时流处理、生产级向量数据库、企业级审计留存。文档中把这些明确列为生产化工作，而不是暗示已经完成。

## 9. 迭代路线

- **V1 · 可复现演示**：打通端到端流程，固定数据与黄金集，保证无密钥可运行。
- **V2 · 更强理解**：增加多轮指代、复杂筛选、混合检索和引用对齐。
- **V3 · 业务集成**：接只读数仓和文档平台，增加租户/角色权限及脱敏。
- **V4 · 决策闭环**：建议进入审批队列，人工确认后再写回业务系统。

每次迭代都必须先扩充评测集，再上线能力，避免“功能变多但可信度下降”。
